DATASET

Working data

You've been asked to design an interns table with this exact specification:

  • intern_id — integer, auto-incrementing, PRIMARY KEY
  • fullName — text up to 60 characters, cannot be empty
  • email — text up to 100 characters, cannot be empty, no two interns may share one
  • stipend — a decimal number, must be between 0 and 100000
  • mentorId — integer, may be left unknown
  • joinedOn — a timestamp that automatically records the moment the row is created
  • isRemote — true/false, defaults to TRUE if not specified
TASKS

Your tasks

1Task 1

Write the full CREATE TABLE interns (...) statement satisfying every rule in the spec above (right datatype, NOT NULL, UNIQUE, CHECK, DEFAULT, PRIMARY KEY, AUTO_INCREMENT where needed).
Hint
Constraints go right after a column's datatype. AUTO_INCREMENT columns still need PRIMARY KEY declared separately at the end.

2Task 2

Write a single INSERT statement (with column names) adding 3 valid interns at once. For at least one of them, explicitly insert NULL for mentorId, and let isRemote take its default by leaving it out of the column list.
Hint
Leaving a column out of the column list entirely is how you let it take its DEFAULT — you don't need to type the word DEFAULT for that.

3Task 3

Write an INSERT that would fail against your schema on purpose. State exactly which constraint it violates and why.
Hint
Try reusing an email from Task 2, or pass a stipend outside the 0–100000 CHECK range, or leave fullName out entirely.

4Task 4

Rewrite Task 3's failing INSERT so it succeeds, changing as little as possible.
Hint
You only need to fix the one value that broke the constraint you identified.
