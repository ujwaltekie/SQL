01

What is CRUD?

Whatever entity a table stores (students, films, orders), only four things can ever be done to its entries. Together they are called CRUD. Tap each card.

Analogy: Think of a notebook of contacts. Writing a new contact is Create, flipping to find one is Read, correcting a number is Update, and tearing out a page is Delete. SQL just says these things to a database in a precise language.

Our practice database: Sakila

Sakila is the official MySQL sample database. It models an old-style DVD rental store: tables for film, actor, customer, staff, store, rental, payment and more. It supports everything such a business does: renting films, tracking inventory, storing customers and staff. We'll use it for most of the course.

Real story · Why rental stores?

Blockbuster ran thousands of such stores. In 2000, Netflix's founders reportedly offered to sell the company to Blockbuster for about $50 million, and Blockbuster passed. A decade later Blockbuster was bankrupt. Both businesses run on the same kind of data: customers, films, rentals, payments, and CRUD on all of it.

02

Create: tables and INSERT

SQL (Structured Query Language) is the language used to talk to relational databases: creating tables, fetching and changing data, managing permissions. "Structured" because it works on data arranged in a fixed structure: tables.

Step 1: CREATE TABLE, the blueprint

Before any row exists, we describe the table: its columns, each column's data type, and its constraints.

CREATE TABLE students (
    id INT AUTO_INCREMENT,
    firstName VARCHAR(50) NOT NULL,
    lastName VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    dateOfBirth DATE NOT NULL,
    enrollmentDate TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    marks DECIMAL(5, 2) CHECK (marks BETWEEN 0.00 AND 100.00),
    batchId INT,
    isActive BOOLEAN DEFAULT TRUE,
    PRIMARY KEY (id)
);
Analogy: This is designing a paper admission form before printing it: which boxes exist, what may be written in each, which are compulsory. Every student then fills in a copy.
Data type says what kind of value a column holds: INT whole numbers, VARCHAR(50) text up to 50 characters, DATE, TIMESTAMP (date and time), DECIMAL numbers with decimals, BOOLEAN true/false. (See the attached video on SQL data types for the full list.)
NOT NULL: the column can't be empty. Leave it out while inserting and you get an error.
UNIQUE: no two rows may share this value. An insert or update that would create a duplicate fails.
DEFAULT: the value used when you don't supply one. enrollmentDate becomes the moment of insertion.
CHECK: a custom rule. Here marks must lie between 0 and 100 or the query fails.
AUTO_INCREMENT + PRIMARY KEY: id is filled automatically (1, 2, 3, ...) and identifies each row, exactly the primary key idea from Lecture 1.

Step 2: INSERT, adding rows

INSERT INTO film (title, description, release_year, language_id, rental_duration, rental_rate, length, replacement_cost, rating, special_features)
VALUES ('The Dark Knight', 'Batman fights the Joker', 2008, 1, 3, 4.99, 152, 19.99, 'PG-13', 'Trailers'),
       ('The Dark Knight Rises', 'Batman fights Bane', 2012, 1, 3, 4.99, 165, 19.99, 'PG-13', 'Trailers');

INSERT INTO names the table and, in brackets, the columns we are filling. VALUES then lists the data, matched to the columns by position: first value to first column, and so on. Several rows can go in one statement, separated by commas, which is faster than many single inserts.

Leaving out the column names

The column list is optional. Without it, values go into the table's columns in their defined order, so you must supply every column:

INSERT INTO film
VALUES (default, 'The Dark Knight', 'Batman fights the Joker', 2008, 1, NULL, 3, 4.99, 152, 19.99, 'PG-13', 'Trailers', default);

NULL means "no value" and default means "use the column's default" (for auto-increment film_id, the next number). It works, but it is bad practice: you must remember the exact column order, one slip puts data in the wrong column, you must fill columns you'd rather skip, and adding a column later breaks the query. Always name your columns.

03

Read: the SELECT statement

SELECT reads data. Its simplest forms:

SELECT * FROM film;
SELECT title, description, release_year FROM film;

* means "every column"; naming columns (comma-separated) returns just those. Keywords and column names are case-insensitive, so SELECT TITLE FROM film is identical. On huge tables, prefer naming columns: fetching only what you need is faster.

Analogy: A spreadsheet where you hide columns you don't need. * is "show all", listing columns is "show only these".

Thinking in loops

Every SQL query can be pictured as a plain loop over rows. From here on we'll pair each query with pseudocode; the tabs below cover the ideas in this lecture.

Same idea as a loop

  
DISTINCT: removing duplicates

  
SELECT DISTINCT rating FROM film;
SELECT DISTINCT rating, release_year FROM film;

  
With one column, you get each value once. With several, uniqueness applies to the combination: (PG, 2006) and (PG, 2008) are different pairs, so both stay, while a second (PG, 2006) is dropped.

  
Analogy: A café's menu lists each flavour once, no matter how many scoops were sold. DISTINCT turns a long sales log into that menu.

  

  
Constants and calculations

  
SELECT 'Hello World';
SELECT title, 'Hello World' FROM film;
SELECT title, length/60 FROM film;
SELECT title, ROUND(length/60) FROM film;

  
SELECT isn't only for stored columns. A constant needs no FROM at all, and next to real columns it repeats on every row. You can also compute on columns: length is in minutes, so length/60 gives hours, and ROUND() (one of many built-in functions we'll meet later) rounds it. The table itself is never changed; only the output is.

  
INSERT ... SELECT: copying between tables

  
INSERT INTO film_copy (title, description, release_year, rating)
SELECT title, description, release_year, rating
FROM film;

  
Instead of typing values, the rows come from a SELECT. The selected columns line up by position with the column list. Think of it as photocopying chosen columns of one register into another.






  04
WHERE: choosing which rows

  
Rarely do we want all rows. WHERE keeps only rows meeting a condition, and it always comes after FROM.

  
SELECT * FROM film WHERE rating = 'PG-13';

  
In loop terms, WHERE is just the if inside the loop (see the WHERE tab above). And like if, it combines conditions.

  
AND, OR, NOT

  
SELECT * FROM film WHERE rating = 'PG-13' AND release_year = 2006;  -- both
SELECT * FROM film WHERE rating = 'PG-13' OR release_year = 2006;   -- either
SELECT * FROM film WHERE NOT rating = 'PG-13';                      -- opposite

  
AND needs every condition true (strict), OR needs at least one (generous), NOT flips the result. Mixing them needs care: AND is evaluated before OR, like multiplication before addition in maths.

  
rating = 'PG-13' OR release_year = 2006 AND rental_rate = 0.99
-- means: rating = 'PG-13' OR (release_year = 2006 AND rental_rate = 0.99)

  
Use parentheses whenever you mix them, so the meaning is obvious to readers and to you. Run both versions in the lab below and compare.

  

  
Comparison operators

  
Besides =, use > < >= <= and !=. MySQL also accepts <> for "not equal": rating <> 'PG-13'.

  
IN and BETWEEN

  
SELECT * FROM film WHERE rating IN ('PG-13', 'R');
SELECT * FROM film WHERE rating NOT IN ('PG-13', 'R');
SELECT * FROM film WHERE length BETWEEN 100 AND 160;

  
IN compares a column with a whole list. It is a tidy replacement for a chain of ORs, and NOT IN reverses it. BETWEEN a AND b checks a range, and both ends are included.

  
NULL: the tricky one

  
NULL means "no value / unknown". It is not zero and not an empty string. Because it is unknown, any comparison with it is unknown too:

  
SELECT NULL = NULL;   -- NULL
SELECT 3 = NULL;      -- NULL
SELECT 3 <> NULL;     -- NULL (not true!)

  
WHERE keeps only rows where the condition is true, so WHERE description = NULL returns nothing, always. Use IS NULL / IS NOT NULL.

  
Analogy: Two exam answer sheets, both left blank. Are the answers "equal"? You can't say; neither answer exists. That's why NULL is not equal to NULL.

  
The hidden trap: WHERE id != 2 silently skips customers whose id is NULL. If you want everyone except 2, including NULLs, say so: WHERE id IS NULL OR id != 2. Many assignment answers go wrong exactly here.

Update and Delete

  
UPDATE film SET release_year = 2006, rating = 'PG' WHERE film_id = 1;
DELETE FROM film WHERE film_id = 1;

  
UPDATE changes the listed columns (SET) on every row matching the WHERE. DELETE FROM removes every row matching the WHERE. Both are simply the loop with an action inside the if: change the row, or remove it.

  
The big danger: forgetting WHERE. The condition is what narrows the action. Leave it out and the action applies to every row: all 1,000 films get the same year, or the whole table is emptied.

  
Analogy: "Find and Replace" in a document. With a selection it changes only that part; with nothing selected and "Replace All" pressed, it rewrites everything. Always write the WHERE first, and preview it with a SELECT.

Quick recap

  
    
  
  • CRUD = INSERT, SELECT, UPDATE, DELETE.
    • 
  
  • CREATE TABLE defines columns, types and constraints (NOT NULL, UNIQUE, DEFAULT, CHECK). Always name columns in INSERT.
    • 
  
  • SELECT picks columns, DISTINCT removes duplicate rows, expressions compute new values, WHERE filters rows.
    • 
  
  • AND before OR, so use parentheses. IN for lists, BETWEEN is inclusive, and NULL needs IS NULL.
    • 
  
  • UPDATE and DELETE without WHERE hit every row.
