The five aggregate functions

From Lecture 3, an aggregate function takes many values from a column and boils them down to a single value. COUNT was our first example. There are four close relatives, and together these five cover almost every summary statistic you'll ever need in SQL.

FunctionWhat it returnsSkips NULLs?Works on text too?
COUNT(col)how many non-NULL valuesyesyes
SUM(col)total of all valuesyesno
AVG(col)SUM ÷ COUNT, the meanyesno
MIN(col)smallest valueyesyes (alphabetical)
MAX(col)largest valueyesyes (alphabetical)

Notice the common thread: every aggregate function ignores NULLs. A NULL is "unknown", and an unknown value can't sensibly be added, averaged, or compared, so SQL simply leaves it out rather than guessing.

Analogy: A class of 6 students sits a test; one student was absent and has no score recorded (NULL, not zero). The teacher reports the class average using only the 5 scores that exist, the total marks of those 5, the topper's score and the lowest score among those 5, and "5 students attempted this test." Nobody pretends the absent student scored a zero.

  03
The three faces of COUNT

  
COUNT is the one aggregate with more than one shape, and mixing them up is a very common bug.

  
SELECT COUNT(*)                    FROM film_list;   -- every row, NULLs included
SELECT COUNT(rental_rate)          FROM film_list;   -- only non-NULL rental_rate values
SELECT COUNT(DISTINCT rental_rate) FROM film_list;   -- only distinct non-NULL values

  
Analogy: A school register. COUNT(*) is "how many names are on the register" (6). COUNT(rental_rate) is "how many students submitted a fee receipt" (5, since Her's is missing). COUNT(DISTINCT rental_rate) is "how many different fee amounts were paid" — since 4.99 was paid twice, that's only 4 distinct amounts.

  04
Combining aggregates, and rounding them

  
Nothing stops you from computing several aggregates in one query. It's just like combining ordinary columns, except every value shown is aggregated:

  
SELECT
  COUNT(*)              AS total_films,
  COUNT(rental_rate)    AS priced_films,
  SUM(rental_rate)      AS total_revenue_if_all_rented,
  ROUND(AVG(rental_rate), 2) AS avg_price,
  MIN(rental_rate)      AS cheapest,
  MAX(rental_rate)      AS priciest
FROM film_list;

  
Remember from Lecture 2 that ROUND(x, 2) rounds to 2 decimal places. Wrapping an aggregate in ROUND is extremely common, since AVG often produces long decimals like 3.79000000000000..., and giving a result a clean alias with AS (Lecture 3/4) makes the output easy to read.

Real story · AVG in the wild
Every product star-rating you've ever seen, Amazon's "4.3 out of 5", an app's rating on the Play Store, is nothing more than AVG(rating) over every review row, typically rounded to one decimal place. A single 1-star review barely moves that average once there are thousands of rows, which is exactly the arithmetic behind why one bad review "doesn't matter much" on a popular product but can sink a brand-new one with only 3 reviews.






  05
ORDER BY + LIMIT: building a Top-N leaderboard

  
A hugely common real-world pattern: "top 5 longest films", "top 10 trending videos", "top 3 highest-paid employees". It's always the same two ingredients from Lecture 3, used together: ORDER BY to rank everything, then LIMIT to cut the list short.

  
SELECT title, length
FROM film_list
ORDER BY length DESC
LIMIT 3;

  
The order matters a lot here: SQL sorts the entire result first, and only then slices off the top N. Asking for LIMIT 3 before sorting would give you 3 random films, then sort just those three, which is not the same thing at all (and isn't even valid SQL syntax; LIMIT always comes last for exactly this reason).

Real story · Trending lists
YouTube's "Trending" tab, Spotify's "Top 50", and Twitter's "Trending Now" are all, at their core, an ORDER BY on some popularity score (views, streams, mentions) computed over a time window, followed by a LIMIT. The ranking constantly changes simply because the underlying numbers behind ORDER BY change every few minutes.

  






  06
Quick recap

  
    
  
  • COUNT, SUM, AVG, MIN, MAX all ignore NULLs; SUM/AVG need numeric columns, MIN/MAX also work on text.
    • 
  
  • COUNT(*) counts rows; COUNT(col) counts non-NULL values; COUNT(DISTINCT col) counts distinct non-NULL values.
    • 
  
  • Multiple aggregates can be combined in one SELECT, aliased with AS, and wrapped in ROUND for clean output.
    • 
  
  • Top-N pattern: ORDER BY the whole result first, then LIMIT — never the other way round.
